Three Readings of RheoNet

The same nine steps — from an uploaded G′/G″ sweep to a material class — told three ways. Pick the reading that matches what you already know.

You hand the program a measured curve. It hands back a guess at what kind of material you have. Here is everything that happens in between — nine steps, no assumed background.

Tidying up the data
1

Redraw every curve at the same size

Your curve might have 11 points read off a printed graph, or 90 from a machine. Every curve gets redrawn using exactly 60 points, evenly spaced, with in-between values filled in by joining the dots.

Why it is built this way An earlier version fed in curves that always had the same number of points. The program quietly began using the number of points itself as a clue — which works perfectly in practice and fails on every real curve. Forcing everything to 60 removes the clue.
2

Record four things at each point

At each of the 60 points: how far along the frequency axis you are, the two measured quantities (G′ and G″), and the ratio between them. The ratio is already implied by the other two, but handing it over directly saves working it out, and it carries a lot of the signal.

3

Note six facts in a separate pocket

Six plain numbers: the typical size of each measured quantity, where the frequency window starts and ends, how wide it is, and the temperature.

In step 2 the frequency track is deliberately re-centred, so the shape is seen without knowing where it sat. That is what lets the same shape be recognised anywhere. But where your measurement sat is genuinely useful — so it is not thrown away, just carried separately.

Reading one curve
4

Slide shape-detectors along the curve

This is the heart of it. There is a set of small detectors, each looking at five neighbouring points at a time, each dragged along the whole curve. One might respond to a steep rise, another to a flattening-off, another to a small bump.

Sliding is the key idea. A detector learns its shape once, then recognises it anywhere. Since measurement windows are cropped at random, the same physical feature turns up in different places on different curves — a detector fixed to one spot would be nearly useless.

This happens in three passes: the first finds small simple shapes, the second combines those into bigger ones, the third combines again. By the end it can respond to features spanning a wide stretch, built up from simple pieces.

5

Summarise what each detector found — twice

Each detector has produced 60 scores, one per point. Too much to carry forward, so it gets boiled down. But boiling down loses information, and which information depends on how you do it. So it is done two ways:

The highest score

Did this shape appear anywhere at all?

The average score

How much of the curve did this shape cover?

Each alone is blind to something The highest score cannot tell a brief blip from something spanning the whole curve. The average cannot spot a single sharp spike — 59 quiet points drown it out. Both blind spots matter here: a shoulder is a spike, a plateau is spread out. So both numbers are kept.
6

Combine it all into one description

The two summaries and the six facts from step 3 are laid side by side, then passed through a small mixing stage that weighs them against each other and condenses them into a single list of 128 numbers.

That list is the description of your curve — not a picture of it, but a summary of which features are present and how strongly.

Combining several curves
7

Decide which curves matter

If you uploaded several curves — the same material at several temperatures — steps 4 to 6 happen to each separately. Now they must become one description.

The obvious move is to average them. That would be a mistake. In a temperature series the answer often lives in one curve, typically the hottest, where the material finally starts to flow within the window you measured. Averaging waters that curve down to a quarter strength.

So instead the curves are weighed, and the weights are worked out by looking at them. Most of the weight might land on one curve. An average is the special case where everything counts equally; this is free to be lopsided when the evidence is lopsided.

Upload only one curve and this step does nothing — one curve gets all the weight. Single curves need no special handling; they are just the simplest case. A useful side effect: the weights can be read afterwards, so you can see which curve the answer rested on.

Producing answers
8

Four answers from the same description

The combined description passes through one more mixing stage, then four separate readouts each take a turn at it:

Which class

A score for each of the 10 material types.

Which broad family

The simpler two-way call. An easier question, and being asked it seems to help with the harder one.

How likely it is wrong

A single number — see step 9.

The fitted numbers

Up to five parameter values, always produced, never withheld.

9

The “am I wrong?” readout

During training this is not shown a human judgement about which cases are hard. It is shown whether the class readout, on that very example, actually got it right. So it learns to predict its own mistakes.

That sidesteps a trap: a program rewarded for hesitating will hesitate constantly; one never rewarded for it will never hesitate. Tying it to real errors avoids both.

It works, measurably: setting aside the 10% of cases it feels shakiest about raises accuracy on the rest from 0.923 to 0.957. Setting aside 30% takes it to 0.996.

The limit worth understanding It only ever learned from mistakes made on the ten known types. Hand it a material that is none of the ten and it has no basis for alarm — it may well report high confidence. It can flag “a difficult example of something I know.” It cannot flag “something I have never seen.” That is why the written report exists, and why a second, completely separate method runs alongside so the two answers can be compared.

In one breath: redraw the curve at a fixed size → note the window details separately → slide shape-detectors along it → summarise what they found two complementary ways → squeeze into one description → if there are several curves, weigh them rather than average → read off the class, the family, a self-doubt score, and the parameters.

The recurring theme: at nearly every step something is deliberately discarded so the program cannot lean on it — the point count, the window position — then handed back separately where it is genuinely informative. Much of the design is about controlling what it is allowed to use as a clue.

The same nine steps, described by what they do to a SAOS spectrum. The right-hand rail names the physical features each step is built to preserve or discard.

Conditioning the spectrum
1

Resample onto a fixed log-ω grid

Any point count, any frequency range, sorted or not, is interpolated onto 60 points evenly spaced in log ω spanning that curve's own window. Interpolation is linear in log–log, which is exact for the power-law segments that dominate these spectra.

Point density therefore becomes a property of the loader, not of the model: a sparse digitized curve and a dense rheometer sweep over the same window give an identical input.

Recorded failure Training at a fixed 60 points taught the model to lean on density itself — a sampling artefact learned as physics. It then failed on every real curve until resampled. The generator now varies the count from 10 to 100 and the loader resamples, so density cannot carry information either way.
Preserved
  • Window span and position
  • All spectral shape
Discarded
  • Point density
  • Point ordering
2

Four channels per grid point

Each point carries log ω (mean-centred), log G′, log G″, and log tan δ. The loss tangent is redundant with the two moduli but supplied directly — it is the quantity that carries much of the discriminating signal, and deriving it costs the encoder capacity.

Mean-centring log ω is deliberate: it presents window shape without window position, so a feature is recognised identically wherever it falls.

Channels
  • log ω, centred
  • log G′
  • log G″
  • log tan δ
3

Six scalars alongside

Median G′ and median G″ (absolute modulus scale), the low and high edges of the window in log ω, its width, and the temperature. These are exactly what step 2's mean-centring removed, returned through a separate route.

Absolute scale matters — a 400 kPa plateau and a 4 kPa one are different materials — but it must not be confused with shape, so it travels apart.

Restored here
  • Modulus scale
  • ω-window placement
  • Window width
  • Temperature
Per-curve feature extraction
4

Convolutions over the frequency axis

Three stacked passes of translation-invariant filters, each spanning five adjacent grid points, swept along log ω. The discriminating features here are local shape in log-frequency: a terminal slope of 2, a plateau, a power-law wing, a G″ shoulder.

Translation invariance is not a stylistic preference — the generator crops windows by up to 2.5 decades at random, so the same physical feature lands at different grid positions on different curves. A position-fixed layer would have to relearn each feature at every position.

Stacking three passes widens the effective span: early filters see a local slope, later ones see features spanning a substantial fraction of the window, such as a broad plateau.

Features sought
  • Terminal slopes (2 and 1)
  • Plateau extent
  • G″ shoulder
  • Power-law wings
  • Crossover
5

Pool each filter two ways: max and mean

Each filter's response along the 60 grid points is reduced twice — by its maximum (did this feature occur anywhere?) and by its mean (over how much of the window did it persist?).

Why both are required here Max alone cannot distinguish a slope of 2 sustained over three decades from a slope of 2 touched at one point — which is precisely the breadth distinction separating a broad BSW spectrum from a sharp reptation terminal. Mean alone dilutes a localised G″ shoulder, the sticker-class signature, across 60 points into nothing. The two failure modes are complementary, so both statistics are retained.
Max catches
  • G″ shoulder
  • Loss peak
  • Crossover
Mean catches
  • Sustained terminal slope
  • Plateau breadth
  • Broad wings
6

Project to one curve descriptor

The two pooled statistics and the six scalars are concatenated and passed through a small projection, yielding a 128-number descriptor of that spectrum — a feature vector, not a reconstruction. Nothing regenerates the curve; there is no reconstruction objective anywhere in the model.

Output
  • One descriptor per spectrum
Pooling a stack
7

Attention over the stack, not an average

Steps 4–6 run independently on each curve of a temperature or concentration stack. Pooling them by simple averaging would be wrong for a specific physical reason: a stack's discriminating information is frequently carried by one curve — characteristically the hottest, where terminal relaxation finally enters the accessible window.

Averaging dilutes that curve by the stack size. Instead the descriptors are combined with learned, input-dependent weights, free to concentrate almost entirely on one member.

This is the mechanism that makes stacks work at all: measured accuracy is 0.898 at N = 1, rising to about 0.94 at N ≥ 2. N = 1 is the degenerate case — a single curve receives unit weight, so no separate code path exists. The weights are recoverable afterwards, showing which curve the call rested on.

Where this matters most The temperature stack is the only route by which a dynamically crosslinked vitrimer is separated from a permanently cured elastomer. That distinction cannot be made from a single isotherm at all, so this pooling step is load-bearing for the taxonomy rather than an efficiency measure.
Stack types
  • Temperature (Arrhenius-tied)
  • Concentration (one scaling law)

Outputs
8

Two heads, four readouts

One shared trunk feeds: the fine class over 10 architectures (zimm, rouse_screened, reptation, sticky_rouse, sticky_reptation, cured_elastomer, critical_gel, wormlike_micelle, branched, star); the regime as a coarser two-way call, trained as an auxiliary task that appears to assist the fine one; an abstention score; and up to five constitutive parameters, always emitted.

Head 1
  • 10 fine classes
  • 2 regimes
  • Abstention
Head 2

9

Abstention, and what it cannot do

The abstention head is trained against whether the classifier actually erred on that example — it learns to predict its own failures, rather than being thresholded onto a confidence score after the fact.

Calibration is good: discarding the least-confident 10% lifts accuracy from 0.923 to 0.957; 20% to 0.982; 30% to 0.996.

It is not an out-of-distribution detector It is trained only against the model's own errors on the synthetic distribution, so a low abstention score is not evidence of a correct answer on material whose class is absent from training — polymer blends, block copolymers, semicrystalline melts, filled systems. The dominant error mode of this classifier is a good fit of the wrong class, which no confidence score flags. That is why every report states the winner's absolute fit quality, ranks alternatives by ΔAICc, and carries an unconditional “don't think it's X?” section even on confident, correct answers.
Not detected
  • Polymer blends
  • Block copolymers
  • Semicrystalline melts
  • Filled / nanocomposite

The design principle running through it: at nearly every step something is deliberately withheld from the model — point density, window position, absolute scale — and reintroduced through a controlled route where it is genuinely informative. Every such choice is an answer to a way the model was previously found to cheat.

Input pipeline
1

Resample to a fixed grid

Log-linear interpolation onto N_GRID = 60 points spanning each curve's own window. Handles unsorted input, clips to EPS = 1e-30, and broadcasts a degenerate single-point curve flat rather than raising.

Leakage found and closed Fixed point count at generation time became a discriminative feature — the model learned sampling density as if it were physics, and generalisation to real curves collapsed. Fixed by two independent changes: randomise the count over (10, 100) in the generator, and resample in the loader regardless. Raw and resampled real curves now yield identical predictions, which is asserted as a test.
shape (n, any) → (60,)
2

Channel stack

N_CHANNELS = 4: mean-centred log ω, log G′, log G″, log tan δ. The fourth is algebraically redundant, included to spare encoder capacity.

3

Summary scalars

N_SUMMARY = 6: log median G′, log median G″, min/max/ptp of log ω, and (T − 298.15) / 50. These re-inject exactly what channel 1's mean-centring removes, bypassing the translation-invariant encoder.

Curve encoder · shared weights
4

3× [Conv1d k=5 · GELU · BatchNorm]

Widths 64 → 96 → 128, padding=2, so length is preserved at 60 throughout. Applied to the flattened B·n_max curves in one pass, then reshaped back.

Translation invariance is the load-bearing property: windows are randomly cropped up to 2.5 decades, so features appear at arbitrary offsets. An MLP on the flat grid would need to learn each feature independently per position, at a fraction of the effective sample size per position, with no weight sharing.

→ (B·N, 128, 60)
5

Global mean ⊕ max over the length axis

Concatenated, not chosen between. Max is invariant to feature extent, mean is insensitive to sharp localised peaks; both failure modes correspond to real discriminators in this domain (plateau breadth vs. G″ shoulder). Costs one concat and no parameters beyond widening the following projection.

pool (B·N, 128, 60)
→ (B·N, 256)
6

Concat summary · Linear · GELU · Dropout · Linear

256 + 6 = 262 → 128. Dropout 0.10. Output is the per-curve embedding. Padded slots are then zeroed by the mask before pooling, so nothing downstream can read them.

→ (B, N, 128)
Set pooling
7

Masked attention pool · 4 heads · learned query

A single learned query vector attends over the stack via MultiheadAttention, with key_padding_mask setting padded slots to −∞ pre-softmax so they contribute exactly zero. LayerNorm follows.

Mean pooling is the wrong inductive bias here: stack information is typically concentrated in one member (the highest temperature, where terminal relaxation enters the window), and a mean attenuates it by 1/N. Attention can place near-unit weight on that member.

N = 1 is the identity — softmax over one element — so single-curve inference needs no separate path. Measured: 0.898 at N = 1 → ~0.94 at N ≥ 2. Attention weights are returned in the output dict for interpretability.

9

Learned abstention: target is the model's own error

The BCE target is (argmax ≠ label), computed under no_grad and detached, so the term shapes the abstention head without back-propagating into the classifier. The head learns to predict its own failures.

This resolves the degenerate objective directly: a model rewarded for abstaining abstains on everything, one never rewarded never abstains. ABSTAIN_WEIGHT = 0.2 keeps it from dominating.
