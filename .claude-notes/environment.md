# Environment (reproducible across PCs)

Locked so every machine runs an identical toolchain. **Do not loosen the pins.**

## The stack
- **Manager:** [uv](https://docs.astral.sh/uv/) (Astral). Manages the Python
  interpreter *and* the packages, so the env does not depend on any
  system-installed Python.
- **Python:** pinned to **3.12** (`requires-python = "==3.12.*"` in
  `pyproject.toml`). uv installs/manages this interpreter itself.
- **Dependencies:** exact versions + hashes locked in **`uv.lock`** (committed).
  `requirements.txt` is an autogenerated **pinned+hashed** export of the same
  lock, kept for pip-only fallback — regenerate it, never hand-edit.

## GPU / PyTorch
`torch` is a locked dependency (2.13.0). **Which build you get is
platform-dependent, by design:** Linux resolves the CUDA extras (`+cu130`),
**Windows resolves `+cpu`** — the CUDA extras carry `sys_platform == 'linux'`
markers. So on a Windows box `torch.cuda.is_available()` is **False even with
an NVIDIA card present**, and that is correct, not a broken install. Do NOT
"fix" it with a per-PC torch variant or a CUDA index (see History 2026-09-03);
at this model size CPU is ~9 s/epoch vs ~11 s/epoch on a GTX 1660 Ti, so there
is nothing to win. Training auto-selects via `device_auto()`.
Corollary worth knowing before you go debugging a "stuck" training run: on
Windows an idle `nvidia-smi` during training is EXPECTED. The real long pole in
`train_classifier.py` is the AICc physics baseline that follows training —
150 test stacks x a 10-candidate bank of SciPy fits, single-threaded, which
takes considerably longer than the 55 epochs do.
Cost of this: `uv sync` pulls ~2.5 GB of CUDA wheels on a fresh machine.
Home PC (2026-09-01): GTX 1660 Ti, ~11 s/epoch at 16k examples.

## Changing dependencies
- Add/remove a package: edit `[project].dependencies` in `pyproject.toml`, then
  `uv lock` (updates `uv.lock`) and `uv sync`.
- Bump everything to latest allowed: `uv lock --upgrade`.
- After any lock change, regenerate the pip fallback:
  `uv export --format requirements-txt --no-emit-project --no-dev -o requirements.txt`
- Commit `pyproject.toml`, `uv.lock`, and `requirements.txt` together.
